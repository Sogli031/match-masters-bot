### 3. `BuildPrioritizedTargets` (`0x05ed002c`)

U `BuildPrioritizedTargets` **i `alreadyPulled` i `allBlocked` (i `avoidTargets`) su zabranjeni kao ciljna polja**. Dakle, `SourcePos` merge swap-a (pošto je u `blocked` = `allBlocked`) jeste **zabranjen kao cilj**. Da li je zabranjen i kao kandidat zavisi od `BuildDominantCandidates` (čiji disasm nije priložen u ovom fajlu).

```csharp
// [KOD: 0x05ed002c]
List<Point> BuildPrioritizedTargets(
    GameLogic logic, Point lotusPos, int maxRadius,
    HashSet<Point> alreadyPulled, HashSet<Point> allBlocked, HashSet<Point> avoidTargets)
{
    var list = new List<Point>();
    for (int dx = -maxRadius; dx <= maxRadius; dx++)         // [KOD: 0x05ed0170..0x05ed02c4]
    {
        for (int dy = -maxRadius; dy <= maxRadius; dy++)
        {
            if ((dx | dy) == 0) continue;                    // [KOD: 0x05ed0198..0x05ed019c] preskace lotos
            var pt = new Point(lotusPos.x + dx, lotusPos.y + dy); // [KOD: 0x05ed01c4]
            if (!logic.Board.IsPointInBound(pt)) continue;   // [KOD: 0x05ed01dc..0x05ed01e0]
            var slot = logic.Board[pt];                      // [KOD: 0x05ed01f4]
            if (slot.byte_0x24 == 0) continue;               // [KOD: 0x05ed01fc..0x05ed0200]
            if (alreadyPulled.Contains(pt)) continue;        // [KOD: 0x05ed0214..0x05ed0218]
            if (allBlocked.Contains(pt)) continue;           // [KOD: 0x05ed022c..0x05ed0230]
            if (avoidTargets != null && avoidTargets.Contains(pt)) continue; // [KOD: 0x05ed0248..0x05ed024c]

        .OrderBy(t => Math.Abs(t.x - lotusPos.x) + Math.Abs(t.y - lotusPos.y))      // [KOD: 0x05ed1b78] Manhattan
        .ThenBy(t => Math.Max(Math.Abs(t.x - lotusPos.x), Math.Abs(t.y - lotusPos.y))) // [KOD: 0x05ed1bf4] Chebyshev
        .ThenBy(/* static cached lambda 1: 0x765d0b8+0x8 */)                        // [KOD: 0x05ed0378..0x05ed03d8]
```

### 4. `BuildCascadePath` (`0x05ed0e20`)

Put **NE SME** da prođe ni kroz `allBlocked`, ni kroz `alreadyPulled`, ni kroz `avoid` (kao ni kroz `visited` ili slot sa `slot+0x24 == 0`), osim ako je sam sused `next == target` (tada odmah završava na `target`). Redosled smerova ide fiksno po statičkom nizu `CardinalDirections` (`0x765caa8`), bira se smer sa **strogo manjim** (`<`) skorom:
`score = Manhattan(next, target) + (Slot[next].MatchesWithColor(dominantColor) ? (BoardWidth * BoardHeight) : 0)` (dakle izbegava pomeranje figura dominantne boje ako postoji put kroz drugu boju). Ako nema nijednog validnog koraka (`bestNext == Point.Zero`), vraća direktni fallback `[source, target]`.

```csharp
// [KOD: 0x05ed0e20]
List<Point> BuildCascadePath(
    Point source, Point target, GameLogic logic,
    HashSet<Point> allBlocked, HashSet<Point> alreadyPulled,
    HashSet<Point> avoid, SlotColor dominantColor)
{
    if (source == target)                                    // [KOD: 0x05ed0f24..0x05ed0f8c]
        return new List<Point> { source };

    var path = new List<Point> { source };                   // [KOD: 0x05ed0f90..0x05ed0fd4]
    var visited = new HashSet<Point> { source };             // [KOD: 0x05ed1000..0x05ed103c]
    int maxSteps = logic.Board.Width * logic.Board.Height;   // [KOD: 0x05ed104c..0x05ed1074]
    Point cur = source;

    while (cur != target && path.Count < maxSteps)           // [KOD: 0x05ed10a8..0x05ed10bc]
    {
        int bestScore = int.MaxValue;                        // [KOD: 0x05ed1120]
        Point bestNext = Point.Zero;                         // [KOD: 0x05ed10dc..0x05ed1108]

        foreach (Point dir in UnifiedFroggyFuAttractionPlanner.CardinalDirections) // 0x765caa8 [KOD: 0x05ed10f8]
        {
            Point next = cur + dir;                          // [KOD: 0x05ed1150]
            if (next == target)                              // [KOD: 0x05ed1160..0x05ed1164]
            {
                bestNext = target;                           // [KOD: 0x05ed12c0..0x05ed12cc]
                break;
            }
            if (!logic.Board.IsPointInBound(next)) continue; // [KOD: 0x05ed1178]
            if (visited.Contains(next)) continue;            // [KOD: 0x05ed1194]
            if (allBlocked.Contains(next)) continue;         // [KOD: 0x05ed11b4]
            if (alreadyPulled.Contains(next)) continue;      // [KOD: 0x05ed11d4]
            if (avoid.Contains(next)) continue;              // [KOD: 0x05ed11f4]
            var slot = logic.Board[next];                    // [KOD: 0x05ed120c]
            if (slot.byte_0x24 == 0) continue;               // [KOD: 0x05ed1214..0x05ed1218]

            int dist = Math.Abs(next.x - target.x) + Math.Abs(next.y - target.y); // [KOD: 0x05ed1234..0x05ed1270]
            int penalty = slot.MatchesWithColor(dominantColor) ? maxSteps : 0;    // [KOD: 0x05ed1274..0x05ed1288]
            int score = dist + penalty;
            if (score < bestScore)                           // [KOD: 0x05ed1290..0x05ed1294]
            {
                bestScore = score;
                bestNext = next;
            }
        }

        if (bestNext == Point.Zero)                          // [KOD: 0x05ed130c..0x05ed138c]
            return new List<Point> { source, target };       // fallback direktan skok

        cur = bestNext;
        path.Add(cur);                                       // [KOD: 0x05ed1350]
        visited.Add(cur);                                    // [KOD: 0x05ed1384]
    }
    return path;
}
```

### 5. Primer A i lista nepoznatih `bl 0x...`

**Šta je dokazivo iz priloženih metoda za Primer A:**
Po `BuildPrioritizedTargets` (`0x5ed002c`), `OrderPiecesOnion` (`0x5ed092c`), `PickBestTarget` (`0x5ed0bcc`) i `BuildCascadePath` (`0x5ed0e20`) sa lotosom `[2,2]` i `blocked = {[2,2], [2,3]}`:
* Iako `RunPullAndConvertLotus` šalje prazan `alreadyPulled` (`pulledSet`) odvojeno od `allBlocked` (`blocked`), **obe** funkcije `BuildPrioritizedTargets` i `BuildCascadePath` proveravaju oba skupa na identičan način (`alreadyPulled.Contains(pt)` i `allBlocked.Contains(pt)`), pa ta razlika sama po sebi ne menja ciljeve ni puteve u Primeru A.
* Po priloženom kodu, `[5,1]` (bomba boje 6, Chebyshev 3, Manhattan 4) je čak **bliži** lotosu `[2,2]` od `[6,2]` (boja 6, Chebyshev 4, Manhattan 4), a pritom je `[6,2]` u igri **povučen** (jer u igri `[5,2]=4` pada na `[6,2]=4`). Ni `StampGatherRegion`, ni `OrderPiecesOnion`, ni `PickBestTarget`, ni `BuildCascadePath` ne mogu isključiti `[5,1]` iz povlačenja.
* Dakle, razlog zašto bomba `[5,1]` u igri ostaje na mestu **mora biti u metodama čiji disasm nije u ovom fajlu**: `UnifiedFroggyFuAttractionPlanner::Pull` (izvršavanje kaskade ili tretman `allBlocked` vs `alreadyPulled`), `UnifiedFroggyFuAttractionPlanner::BuildDominantCandidates` (selekcija kandidata i upotreba 6. argumenta `allBlocked`), ili `ResolveMatchForLotuses` / `ResolveNextPlan` (punjenje `blocked`, `plan+0x58` / `secondaryCells`, ili obrada merge swap-a pre `RunPullAndConvertLotus`). `[PRETPOSTAVKA]` (za potpuni dokaz potreban je disasm za `Pull`, `BuildDominantCandidates`, `ResolveMatchForLotuses` i `ResolveNextPlan`).

**Pravilo (sažetak):**
`StampGatherRegion` samo čita tablu i nikada ne menja `slot+0x24/+0x25` niti `blocked`, pa ne može promeniti pokretljivost figura u `Pull`-u. `RunPullAndConvertLotus` prosleđuje `blocked` po referenci kao `allBlocked` (`+0x30`), dok za `alreadyPulled` (`+0x38`) kreira prazan `HashSet<Point>()` (i tek posle `Pull`-a dodaje izvučena polja i lotos u `blocked`), a `this+0x120` je lista za snimanje poteza (`recorder`). `BuildPrioritizedTargets` zabranjuje i `allBlocked` i `alreadyPulled` i `avoidTargets` kao ciljeve, a `BuildCascadePath` zabranjuje prolazak puta kroz sva ta polja (osim direktnog ulaska na `target`) i bira smer po minimalnom `Manhattan(next, target) + (boja == dominantColor ? W*H : 0)`. Pošto se u ovim funkcijama ništa ne razlikuje što bi preskočilo bombu `[5,1]` u Primeru A, uzrok njenog ostanka mora biti u funkcijama `Pull`, `BuildDominantCandidates` ili `ResolveMatchForLotuses`/`ResolveNextPlan` čiji disasm nije priložen.
