## 1. (C) `BoardAnalyzer::GetAreaOfEffectDestructionSlots` (`0x5da3538`)

### Gde se obrađuje `SlotValue == 40` (`0x28`, lotos)?
**Nigde u ovom metodu nema posebne grane za `SlotValue == 40`, niti se poziva išta iz `FroggyFu`.** Evo šta svaka grana i lambda zaista proverava:

- **Lambde za selekciju u talasima (`b__0..b__12`):**
  - `b__0` `[KOD: 0x5daabb8]` i `b__5` `[KOD: 0x5daaf64]` (specijali koji nastavljaju lanac):
    Vraćaju `true` samo ako:
    `(slot.IsSpecial || slot.SlotValue == 2 || (slot.SlotValue >= 17 && slot.SlotValue <= 20)) && (slot.IsExplodeOnHit || slot._flag28 != 0)`.
    Pošto lotos ima `SlotValue == 40` (`0x28`) i `IsSpecial == false` (`+0x25 = 0, +0x21 = 0`), obe lambde vraćaju **`false`** `[KOD: 0x5daac04-0x5daacec, 0x5daafbc-0x5dab0b8]`.
  - `b__1` `[KOD: 0x5daad14]` i `b__6` `[KOD: 0x5dab0d0]`: proveravaju bit 5 od `slot+0x18` (`(slot._flags18 >> 5) & 1`). Lotos u `PlaceLotusesAndContinue` dobija samo bit 0 (`|= 1`), pa vraćaju **`false`**.
  - `b__2` `[KOD: 0x5daad40]` i `b__7` `[KOD: 0x5dab15c]`: proveravaju `slot.SlotValue == 16 && slot.IsExplodeOnHit` (pečurke).
  - `b__3` `[KOD: 0x5daadac]` i `b__8` `[KOD: 0x5dab210]`: proveravaju `board.GetCell(pos) != 0`.
  - `b__22_4` `[KOD: 0x5daa5c4]`: `p => p._field68` (selektuje `SpecialAbility` igrača za poziv `StartAreaOfEffectProcessing()`).

```csharp
SlotColor PickRevertColor(GameLogic logic, Point lotus, SlotColor originalColor) {
    // Ako je originalColor 0, 1 ili 12 (bitmask 0x1003): vraca odmah
    if ((uint)originalColor <= 12 && ((1 << (int)originalColor) & 0x1003) != 0)
        return originalColor;                                   // [KOD: 0x5eccca4-0x5ecccc4]

    var availableColors = logic._boardConfig_60?._colors_18;    // [KOD: 0x5ecccec-0x5eccd00]

    foreach (Point d in dirs) {
        Point np = new Point(lotus.x + d.x, lotus.y + d.y);     // [KOD: 0x5ecce3c-0x5ecce4c]
        if (!logic.boardModel.IsPointInBound(np)) continue;     // [KOD: 0x5ecce60]
        byte c = logic.boardModel[np].Color_10;                 // [KOD: 0x5ecce78-0x5ecce8c]

        neighborColors.Add(c);                                  // [KOD: 0x5ecsed4]
    }

    // Ako nijedan ortogonalni sused nema originalColor -> vraca originalColor (0 RNG!)
    if (!neighborColors.Contains(originalColor))                // [KOD: 0x5eccf00-0x5eccf04]
        return originalColor;

    if (safeColors.Count == 0) return originalColor;            // [KOD: 0x5eccf68]
```

## 3. (C) Šta se dešava kad eksplozija pogodi lotos (zašto 18 i 29 RNG razlike?)

- Iz `GetAreaOfEffectDestructionSlots` (`0x5da3538`) i `RevertLotuses` (`0x5ec30f4`) vidimo dve ključne činjenice:
  1. `GetAreaOfEffectDestructionSlots` ne vraća lotos u boju (`PickRevertColor`), nego ako `GetAreaOfEffectByPiece` vrati poziciju lotosa, ta pozicija ulazi u `positionsToDestroy` `[KOD: 0x5da4574]`.
  2. U `RevertLotuses` postoji eksplicitna provera `if (slot.SlotValue != 0x28) continue;` `[KOD: 0x5ec3304]` — što potvrđuje da lotos može nestati sa table *pre* `RevertLotuses`.
- **Odgovor za 18 i 29 RNG izvlacenja:**
  - Sama dopuna jednog praznog polja troši samo nekoliko RNG poziva (`GetRandomColor` + prag sprečavanja spoja), ali kada lotos nestane i nastane **rupa za dopunu**, figura iznad pada i dopunjava se novo polje, što u Square Match-u pokreće **novu kaskadu / 2x2 ili linija spoj / novi specijal**, a svaka kaskada troši ~10–30 RNG poziva!
  - `[PRETPOSTAVKA — treba potvrditi kodom]` Da li se lotos pretvara u rupu u `DestroyMatches` / `DamageSlots`, da li daje skor (`slot+0x1c = 0`, pa verovatno 0 ili specijalni skor) i da li se briše iz `LotusPositions` odmah pri uništenju ili tek u `RevertLotuses` / `AfterDestroy` vidi se u **`BoardAnalyzer::GetAreaOfEffectByPiece` (`0x5da57d4`)**, **`GameLogic::DestroyMatches` (`0x5dd2b9c`)** i **`BoardModel::DamageSlots` (`0x5e0ac48`)**.

## 4. (D) `BoardModel::GetSlotPrioritize` (`0x5e0d2d8`)

```csharp
List<Point> GetSlotPrioritize(
    RandomWrapper random, int amount,
    Func<int, int, bool> prioritize, Func<int, int, bool> ignore)
{
    var result = new List<Point>();                             // [KOD: 0x5e0d414]

    // 1) Prvo skuplja polja koja NISU ignore i JESU prioritize:
    List<Point> prioritized = this.Where((x, y) =>
        (ignore == null || !ignore(x, y)) && prioritize(x, y)); // [KOD: 0x5e0d43c]

    List<Point> pool = prioritized;
    if (prioritized.Count < amount) {                           // [KOD: 0x5e0d44c-0x5e0d450]
        result.AddRange(prioritized);                           // [KOD: 0x5e0d46c]
        // 2) Zatim skuplja preostala polja koja NISU prioritize i NISU ignore:
        pool = this.Where((x, y) =>
            !prioritize(x, y) && (ignore == null || !ignore(x, y))); // [KOD: 0x5e0d470-0x5e0d4b0]
    }

    // 3) RNG: mesa CEO pool (ne samo izabrane!):
    List<Point> shuffled = ListExtensions.Shuffle(pool, random); // [KOD: 0x5e0d4e4] (bl 0x3f418fc)

    // 4) Uzima prvih (amount - result.Count) elemenata sa pocetka liste:
    while (result.Count < amount && shuffled.Count > 0) {       // [KOD: 0x5e0d4ec-0x5e0d5a0]
        result.Add(shuffled[0]);                                // [KOD: 0x5e0d530]
        shuffled.RemoveAt(0);                                   // [KOD: 0x5e0d594]
    }
    return result;
}
```
- **Redosled kandidata:** Po `BoardModel::Where` (`0x5e0c6f8`, redosled obilaska table).
- **RNG izvlacenja:** **Po kandidatu u `pool`-u** (preko `0x3f418fc` = `Shuffle(pool, random)`), a **ne** samo po broju `amount`! U `MultiplierMushroomsBoard::GetConvertPoints` (`0x5e356d4`), `prioritize` uvek vraća `false`, pa je `prioritized.Count == 0 < amount` i uvek se meša ceo `pool` svih ne-ignorisanih polja.
- **Šta znači `bool` argument:** Sam `GetSlotPrioritize` **nema** `bool` argument (ima 4 argumenta: `random, amount, prioritize, ignore`). Taj `bool allowEdges` postoji samo u potpisu `MultiplierMushroomsBoard::GetConvertPoints`, gde se u verziji 5.900 uopšte ne prosleđuje ni u `DisplayClass7_0` ni u `IgnorePosition` `[KOD: 0x5e35774-0x5e35778]`.

  ```csharp
      return logic.randomWrapper.Range(minVal, maxVal + 1);     // [KOD: 0x5ec6c18-0x5ec6c28]
  }
  ```
  - **RNG u `RollIntRangeForActivation`:** **1 poziv** `RandomWrapper::Range(minVal, maxVal + 1)` kada je `maxVal >= 1`.
  - Kada se tačno poziva (`RollEntranceMushroomTargetForActivation` -> `this+0x80`) nije u ovom fajlu (`[PRETPOSTAVKA]` — najverovatnije u `FroggyFu::OnPlayerAbilityActivated` / `Use`, ili u kuki kraja poteza).

## 7. (D) Zašto igra vuče **140 RNG MANJE** od simulatora u običnom potezu na Mighty Mushrooms?

Pošto je na snimku `20261120_041307` **prvi talas tačan**, a ista mapa sa Foxy Roxy SE je **15/15 tačna**, razlika od **140 RNG manje** u igri ne dolazi ni od `StampScore` (koji ne menja `IgnorePosition` niti troši RNG), ni od `OnMoveStart` / `OnRebuildAndPassiveInUse` (0 RNG).

Iz priloženog koda postoje **tri konkretna mesta** gde Froggy Fu može promeniti broj kandidata ili broj poziva `GetSlotPrioritize` / dopune posle prvog talasa (`[PRETPOSTAVKA — zahteva proveru preostalih metoda]`):

1. **Ponašanje lotosa pri padanju (`DropSlotsDown` / `RefillSlots`) kad je već na tabli (`Phase == 2`):**
   Lotos ima `HasPiece_24 = 0` i `Movable_25 = 0` `[KOD: 0x5ec54bc]`. Ako je na tabli već bio lotos (iz prethodnog poteza) u ili ispod kolona zahvaćenih potezom `(0,1)->(0,2)`, pitanje je da li `DropSlotsDown` / `RefillSlots` tretira lotos kao prepreku ili pokretan slot. Razlika u tome koje ćelije ostaju kao rupe dopune (`availablePoints` za `MultiplierMushroomsBoard::GetConvertPoints`) direktno menja veličinu `pool`-a koji se šafluje u `GetSlotPrioritize` (~30–45 RNG po šaflovanju) i kaskade posle prvog talasa — što lako daje razliku od 140 RNG!
2. **Pozivaoci `RollEntranceMushroomTargetForActivation` (`0x5ec387c`) i `FroggyFu` pasivi / kuke za pečurke:**
   Samo postojanje metode `RollEntranceMushroomTargetForActivation` na `FroggyFu` (`this+0x80`) dokazuje da Froggy Fu ima **specijalnu integraciju sa pečurkama**! Ako `FroggyFu` (ili `MultiplierMushroomPieceLogic` kad detektuje Froggy Fu / `LotusPositions` / `_stampedPositions_128`) menja koliko se pečuraka konvertuje (`amount`) ili koje tačke idu u `availablePoints` / `ignore` (npr. da ne spawnuje pečurke ili da ih ograniči kad ima lotosa/stampa, čime bi u igri bilo **manje talasa / manje poziva `GetConvertPoints`** = ~140 RNG manje!), to bi odmah objasnilo zašto je samo Froggy Fu 8/8 netačan dok Foxy Roxy SE daje 15/15.
3. **`FroggyFu` kuka kraja poteza / posle uništenja (`OnPlayerMoveEnd` / `AfterDestroy` / `ResolveMatchForLotuses`):**
   Ako `FroggyFu` ima pasivnu metodu koja se okida i na običnom potezu kad je `Phase == 2` (npr. `PlayerMoveEnd` ili `AfterDestroy`), ona može menjati tok pre nego što se pozove `MultiplierMushroomsBoard::GetConvertPoints`.
